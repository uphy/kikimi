# 49. ディクテーションの機械的なフィラー除去

ディクテーションの確定テキストから、「えっと」と節の頭の「え、」を、LLM を使わず規則で取り除く設計。

参照元: `docs/design/25-dictation-mode.md`（D2 の LLM 整形）,
`docs/design/29-dictation-history.md`（`entry.json` の `raw_text` / `final_text`）,
`docs/design/31-dictation-two-pass-decode.md`（確定 raw の選び方）。

## 1. 現状と課題

フィラーを取り除く手段は LLM 整形（`dictation.refine`）しか無い。整形は約1秒の待ちが入るため
オフで使われており、その間はフィラーがそのまま挿入される。

## 2. 実測

規則は、手元の履歴で数えた結果から決めた（2026-11-12 時点）。

ディクテーション履歴 100 件（すべて整形オフ・バッチ確定、約1万字）の `final_text`:

| 形 | 件数 |
|---|---|
| 文頭・読点の直後の「え」「ええ」（「え、50分という」「なので、え10分の」） | 31 |
| 「えっと」 | 1 |
| 読点なしで文中に埋まった「え」（「というえその枠」） | 数件（除去しない） |

会議の `refined.jsonl`（単独整形の 7,228 セグメント）で、raw にある語を LLM が整形後にも残した割合:

| 語 | raw での出現 | 残した割合 |
|---|---|---|
| えっと・えーと・ええと・えーっと・えー | 1,378 | 0.4% |
| あの | 1,272 | 2.8%（「あの時」「あのグラフ」） |
| まあ | 1,102 | 13.6% |
| なんか | 529 | 17.0% |
| こう | 488 | 40.2% |
| その | 566 | 62.9% |

「えっと」系はフィラー以外の用法がほぼ無い。「あの」以下は本来の意味で使う例が混じり、
文字列だけでは区別できない。

## 3. 決定事項

| ID | 決定 |
|---|---|
| FS1 | 確定 raw（`DictationRawSelection` の結果）に純粋関数 `DictationFillerStripper.strip` をかけ、その結果を HUD 表示・LLM 整形の入力・挿入に使う。整形のオン・オフに関係なく効く |
| FS2 | 迷う形は消さない。意味のある読みが残りうる形（下の「消さないもの」）には触れない。取りこぼしは許し、誤って消すことを避ける |
| FS3 | 節の境界（テキストの先頭、「。？！」・改行・読点の直後）にあるフィラーを、直後の読点ごと消す |
| FS4 | 「えっと」「えーと」「えーっと」は節の途中でも消す。直後の読点は残す |
| FS5 | 除去の結果に文字・数字が1つも残らないときは、元のテキストを返す（フィラーだけの発話を黙って捨てない） |
| FS6 | `dictation.strip_fillers`（既定 `true`）で切れる。設定画面の「入力」タブにトグルを置く |
| FS7 | `entry.json` の `raw_text` は発話どおりのまま残す。`final_text` が除去後になる |
| FS8 | 会議の書き起こしには入れない。会議側は LLM 整形が常に通り、raw の表示は整形までの一時的なもの |

### 3.1 消すもの（FS3 / FS4）

| 形 | 条件 | 例 |
|---|---|---|
| えっと・えーと・えーっと・ええっと | 節の境界。または節の途中で、直前が漢字でも「え」でもない | 「なので、えっと分ける」→「なので、分ける」 |
| ええと | 節の境界にあり、直後が読点かテキストの終わり | 「ええと、確認します」→「確認します」 |
| えー | 節の境界にあり、直後が「？」「！」でない | 「えー本日の議題」→「本日の議題」 |
| ええ | 節の境界にあり、直後が読点 | 「見える。ええ、本当の」→「見える。本当の」 |
| え | 節の境界にあり、直後が読点か、漢字・カタカナ・英数字 | 「え、50分」→「50分」、「なので、え10分」→「なので、10分」 |

### 3.2 消さないもの（FS2）

| 形 | 理由 |
|---|---|
| 「え？」「えー！」「えーっ」 | 驚き・聞き返し |
| 「え」＋ひらがな（「えそうなの」「というえその枠」） | 語の一部と区別できない |
| 節の途中の「え」「えー」（「推測のえ根拠」） | 「考え」「とはいえ」「うえ」と区別できない |
| 「ええ」＋読点以外（「ええ感じ」「ええと思う」） | 関西方言の「いい」 |
| 漢字の直後の「えっと」（「言えっと」） | 送り仮名の「え」 |
| あの・まあ・なんか・その・こう・あ、・はい・うん | 2 章の実測のとおり、本来の用法と区別できない |

## 4. 配線

`DictationController` のキーを離した後の処理で、`DictationRawSelection.select` の直後に入れる。

- `selection.rawText` は変えない。履歴の `raw_text` と `raw_source` はここから取る（FS7）
- 除去後のテキストを HUD の表示、`refineForHistory(rawText:)`、挿入に渡す
- 整形がオフ・失敗・タイムアウトのとき、`final_text` は除去後のテキストになる

`docs/design/29-dictation-history.md` §3.2 の「`final_text` は成功時以外 `raw_text` に一致」は、
`strip_fillers` がオンで除去が起きた発話では成り立たなくなる（同文書に追補）。

## 5. 効果の見込み

3.1 の規則を 2 章の履歴に当てた結果:

- ディクテーション 100 件のうち 20 件が変わり、32 か所が消えた。32 か所はすべて目で確かめ、フィラーだった
- 取りこぼし: 「ええ会議側にも」（「ええ」＋漢字）と、読点なしで文中に埋まった「え」

## 6. テスト

- `DictationFillerStripperTests`: 3.1 の各形、連鎖（「えっと、え、ええ、」）、3.2 の各形が変わらないこと、FS5
- `DictationControllerHistoryTests`: `strip_fillers` のオン・オフで `final_text` が変わり、`raw_text` は変わらないこと
- `DictationConfigTests`: `strip_fillers` の既定値と明示の `false`

## 7. スコープ外

- 「あの」「まあ」を文脈で判定すること（形態素解析や LLM が要る）
- 会議の書き起こしへの適用（FS8）
- 言い直し・繰り返しの除去
