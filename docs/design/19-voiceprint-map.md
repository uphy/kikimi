# 19. 話者マップ（声紋 embedding の 2D 可視化）

Settings の話者タブは現在、名前・作成日・更新日の一覧しか出していない（`SettingsView.swift` の
`VoiceprintSpeakerRow`）。一方で各話者は 256 次元 L2 正規化済み WeSpeaker embedding を持ち、
距離関数 `VoiceprintStore.cosineDistance`（`1 - cosθ`、小さいほど近い）も既にある。
この材料を使って「声同士の近さが視覚的に分かる」2D 散布図（話者マップ）を追加する。

`docs/design/13-speaker-diarization.md` 14 章で deferred とした「声紋 DB の管理 UI の拡充」の
第一歩に当たる（閲覧のみ。マージ等の操作は含まない）。

## 1. 目的と非目的

- **目的**
  - 登録話者の「声の近さ」を平面上の距離として一目で把握できるようにする
  - **同一人物の疑い**（cosine 距離が照合閾値未満のペア）を明示的に警告し、重複登録の発見につなげる
  - 選択した話者について「似ている順 + 真の距離」を確認できるようにする
- **非目的**
  - 話者のマージ・リネーム操作そのもの（将来機能。本マップはその判断材料を提供する入口）
  - Recording 中のセッション内スロットのリアルタイム可視化（対象はグローバル声紋 DB のみ）
  - t-SNE / UMAP 等の非線形次元削減（数人〜数十人の規模には過剰で、非決定論的）

## 2. 全体像: 3 層構成

| 層 | 役割 | 距離の出所 |
|---|---|---|
| 散布図（話者マップ） | 全体感。近い声が近くに見える | 2D 射影（歪みあり・目安） |
| 閾値ペア警告（エッジ + ⚠） | 「同一人物では？」の判断材料 | **256 次元の真の cosine 距離** |
| 選択話者の近接リスト | 個別確認。似ている順トップ N + 距離値 | 同上 |

**不変条件**: 同一人物疑いの判定・距離値の表示は必ず 256 次元の `cosineDistance` で計算する。
2D 座標から距離判定を導出してはならない（3 章の歪みがあるため、2D は常に「目安」扱い）。

## 3. 2D 配置の計算: PCA（古典 MDS と数学的に等価）

### 3.1 なぜ MDS ではなく PCA か

cosine 距離 `1 - cosθ` は Euclid 距離ではないため、そのまま古典 MDS（Torgerson）の距離行列に
入れると負の固有値が出て歪む。一方 embedding が L2 正規化済みなら

```
‖a - b‖² = 2 × (1 - cosθ) = 2 × cosineDistance(a, b)
```

が恒等的に成り立ち、この Euclid 距離での古典 MDS は**中心化した embedding 行列の PCA と同一の結果**になる。
つまり N×N 距離行列の構築・二重中心化は不要で、ベクトルを直接 PCA するのが最も単純かつ正しい。

### 3.2 アルゴリズム

入力: 話者 N 人の embedding（各 256 次元）。出力: 各話者の (x, y) 座標。

1. **正準順序化**: 話者を id 辞書順にソートしてから計算する。以降の全演算（浮動小数点の
   総和順序含む）が入力順に依存しなくなり、「シャッフルしても座標がビット一致」が成り立つ
2. **除外判定**（7 章の失敗モードと対応。**正規化より前**に行う）: embedding が
   空 / NaN・Inf 含み / ゼロベクトル（ノルム 0。正規化で 0 除算 → NaN になるため）/
   基準長と不一致（基準長 = 最多数派の embedding 長、同数なら長い方）の話者を除外し、
   除外理由とともに戻り値で報告する（6 章）
3. 残った各 embedding を防御的に L2 正規化する（`VoiceprintExtractor` が正規化済みを保証するが、
   `cosineDistance` と同様に正規化非依存にしておく）
4. 平均ベクトルを引いて中心化 → 行列 X（N×256）
5. Gram 行列 G = X Xᵀ（N×N）の上位 2 固有対を **pure Swift の power iteration + deflation**
   で求める（G' = G − λ₁·v₁v₁ᵀ で 2 本目）。開始ベクトルは固定（決定論）、収束判定は
   固定の許容誤差 + 反復上限。N ≪ 256 なので一瞬で収束する。
   Accelerate / LAPACK（`ssyev`）を使わない理由: 旧インターフェースは macOS 13.3+ で
   deprecated、新インターフェースは `ACCELERATE_NEW_LAPACK` の C マクロ定義が必要で、
   pure Swift の SPM ターゲットでは `Package.swift` と `project.yml` の両方に unsafeFlags を
   通す摩擦がある。上位 2 固有対だけなら power iteration が数十行で済み依存も増えない
6. 座標 = (√λ₁·v₁, √λ₂·v₂)。**√ を取る前に負の固有値は 0 にクランプする（λ = max(λ, 0)）**。
   G = XXᵀ は理論上半正定値だが、丸め誤差で λ₂ がわずかに負（例: -1e-6）になり得る。
   特に話者 2 人（5 章で明示サポート）は λ₂ の理論値が 0 なので負に落ちやすく、
   クランプしないと √λ₂ が NaN となって「y = 0 の 1 次元配置」が壊れ、
   NaN 座標の点が描画に流れる
7. **符号規約**で決定論化: 各軸について、絶対値最大の成分（同値なら正準順序で先頭）が
   正になるよう軸の符号を固定。手順 1 の正準順序化により、このタイブレークも入力順に依存しない

- 決定論的（同一入力 → 同一出力）なので golden 値の単体テストが書ける
- 寄与率（λ₁+λ₂ が全分散に占める割合）は UI には出さない（解釈負担が大きい）。
  歪み対策は数値表示ではなく 4 章のエッジ描画で担保する

### 3.3 レイアウトの安定性

話者の追加・削除・Ended 時の移動平均更新（`applyMovingAverageUpdate`）で embedding が動くと
PCA 軸は回転し得るため、開くたびに配置が多少変わるのは仕様として許容する。ただし
**軸の符号反転（地図が鏡像に飛ぶ）だけは 3.2 の符号規約で抑える**。
前回レイアウトへの Procrustes 整列（回転合わせ）は、話者数が増えて配置の連続性が問題になってから
検討する（現時点では過剰）。

## 4. 歪みへの安全装置

256 → 2 次元の射影では「2D で近く見えるが実際は遠い」（またはその逆）が普通に起きる。
以下をルール化する。

- **閾値ペアのエッジ**: 真の cosine 距離が `diarization.speaker_match_threshold`（config、既定 0.45）
  **未満**（`findBestMatch` と同じ strictly `<`）のペアは、散布図上に破線エッジ + ⚠ アイコン + 距離値を描く。
  2D 上でどれだけ離れて見えても必ず描く
- **閾値円は描かない**: 2D 上の固定半径の円は射影の歪みで嘘になるため
- **軸・目盛は描かない**: PCA 軸に意味はない。「距離は相対的な目安です」の注記のみ置く
- **真の距離の表示**: 点のホバー/選択で近接リスト（5 章）に 256 次元の距離値を出す

## 5. UI 設計

Settings ウィンドウの話者タブを拡張する。上部にマップ、下部に既存のリスト。

```
┌──────────────────────────────────────────────┐
│ 話者マップ（近いほど声が似ています・距離は目安）    │
│ ┌──────────────────────────────────────────┐ │
│ │            ● 田中                          │ │
│ │   ● 佐藤 ⚠┄┄┄┄● 鈴木     ← 破線エッジ      │ │
│ │      （0.42）                              │ │
│ │                        ● 山田              │ │
│ └──────────────────────────────────────────┘ │
│ ⚠ 佐藤 と 鈴木 は声紋が近く、同一人物の可能性があります │
├──────────────────────────────────────────────┤
│ 佐藤          作成: … 更新: …            [🗑] │
│  └ 近い順: 鈴木 0.42 ⚠ / 田中 0.71 / 山田 0.88 │
│ 鈴木          作成: … 更新: …            [🗑] │
│ …                                            │
└──────────────────────────────────────────────┘
```

- **描画**: SwiftUI `Canvas`。点 + 名前ラベル。座標はビュー矩形にパディング付きでフィットさせる。
  2D 上で点が接近・重複したときのラベルの段ずらしは（分散 ≈ 0 の場合に限らず）一般ルールとして適用する
  — 射影の潰れで「真は遠いが 2D で重なる」も起きるため
- **選択**: 点またはリスト行のクリックで相互ハイライト。選択中の話者の行の下に
  近接リスト（似ている順トップ 3 + 距離値、閾値未満には ⚠）を展開する。
  選択中の話者が削除されたら選択状態を解除する（`refreshVoiceprintSpeakers()` 後の再計算と同時）
- **警告バナー**: 閾値未満のペアが 1 組以上あればマップ下に文言で列挙する
  （マップを読み解けなくても気付けるように）
- **人数による縮退**:

  | 話者数 | 表示 |
  |---|---|
  | 0 | 既存の空状態文言のみ（マップ非表示） |
  | 1 | マップ非表示（比較対象がない）。リストのみ |
  | 2 | 表示する（PCA は第 1 主成分のみ有効。y = 0 の 1 次元配置になるが 2 点なら十分） |
  | 3+ | フル表示 |

## 6. 実装

| 対象 | 内容 |
|---|---|
| 新規 `Kikimi/Diarization/VoiceprintMapLayout.swift` | pure な計算層（下記 API）。すべて `nonisolated` の純関数で単体テスト可能。**ログは出さない**（除外は戻り値で報告し、呼び出し側でログする） |
| 新規 `Kikimi/Views/VoiceprintMapView.swift` | Canvas 描画 + 選択状態 |
| `SettingsViewModel` | `refreshVoiceprintSpeakers()` 後にレイアウト・閾値ペア・除外話者を計算して `@Published` で公開（除外話者はここで warning ログ）。N が小さいので同期計算で十分 |
| `SettingsView` | 話者タブにマップ + 警告バナー + 近接リスト展開を組み込む |

**`VoiceprintMapLayout` の API**（3 つとも 3.2 手順 1〜2 の正準順序化・除外判定を共通の前処理として通す）:

- `compute(speakers:) -> (points: [SpeakerPoint], excluded: [ExcludedSpeaker])` — PCA + 符号規約。
  除外話者は理由（`empty` / `nonFinite` / `zeroVector` / `lengthMismatch`）付きで返す
- `closePairs(speakers:threshold: Double) -> [ClosePair]` — 全ペア O(N²) の真の距離、閾値未満の抽出。
  比較は `findBestMatch` と同一意味論・同一方向: **`Double(cosineDistance) < threshold`（strictly `<`、
  distance を Double に昇格）**。threshold を Float に丸める方向は 0.65 が Float で正確に表現できず
  境界判定が食い違い得るため禁止
- `neighbors(of:in:topN:) -> [Neighbor]` — 5 章の近接リスト（閾値と無関係に似ている順トップ N + 距離値）
  を供給する。ソート規則は `KnownSpeakerSort` と同じ「距離昇順、同値なら `updatedAt` 降順」に揃える

その他:

- 依存追加なし（Accelerate も使わない。3.2 手順 5 参照）
- 閾値は `AppConfig` の `diarization.speaker_match_threshold` を読む。`SettingsViewModel` には
  閾値を init 注入可能にする（既定は `AppConfig.shared` 読み。VM テストが実 config ファイルに
  依存しないようにするため）。あわせて `SettingsViewModel` 冒頭の
  「`AppConfig.shared` does not exist yet」という stale コメントを更新する
- 見積り: 0.5〜1 日（Canvas のヒットテスト・ラベル段ずらし・エッジ描画は前例がなく UI 側で上振れし得る）

## 7. 失敗モード

| 状況 | 挙動 |
|---|---|
| embedding が空（**声紋リセット済みを含む**。design 13 §4.4「声紋リセット」） | マップ・エッジ・近接リストから除外（一覧リストには「声紋未登録」バッジ付きで表示）。**意図的な状態なので warning ログは出さない**（除外理由 `empty` は正常系） |
| embedding が長さ不一致（基準長 = 最多数派長）・NaN/Inf 含み・ゼロベクトル | その話者をマップ・エッジ・近接リストのすべてから除外（一覧リストには通常どおり表示）。除外は `compute` の戻り値で報告し、`SettingsViewModel` が warning ログを出す。`cosineDistance` が `.infinity` を返す規約と整合 |
| 全話者がほぼ同一点（分散 ≈ 0） | 点が重なるのは許容（ラベル段ずらしは 5 章の一般ルールで対応）。このとき閾値エッジ・警告バナーが必ず出るため、状況は文言側で伝わる |
| power iteration が収束しない（反復上限到達） | その時点の近似解を使う（PSD 行列では実害なし）。全要素が非有限になった場合のみマップ非表示・リストのみ + warning ログ（会議機能には一切波及しない） |

## 8. テスト

- `VoiceprintMapLayout.compute`:
  - 恒等式の検証（3 点以下・厳密）: 既知ベクトル集合で、2D 座標間の Euclid 距離² ≈ 2×cosineDistance。
    中心化後の rank が 2 以下なので射影に情報損失がなく、恒等式が厳密に成り立つ
  - golden 座標の検証（4 点以上）: 固定 fixture に対して期待座標（符号規約込み）との一致を確認する。
    **4 点以上で「対距離の単調順序の維持」を一般不変条件として検証してはならない** —
    PCA の 2D 射影は対距離の順序を保存しない（それこそが 4 章で警告している歪みそのもの）ため、
    正しい実装に対してテストが落ち得る
  - 決定論: 同一入力 → 同一出力。話者の順序をシャッフルしても各話者の座標が不変
    （3.2 手順 1 の正準順序化によりビット一致で検証できる）。
    4 点以上の一般入力に対する検証対象はこの決定論と golden 座標のみ。
    golden fixture は固有値が明確に分離した配置を選ぶ（λ₁ ≈ λ₂ の縮退スペクトルでは
    固有ベクトル基底に回転自由度があり、符号規約では吸収できないため対称配置を避ける）
  - 縮退: 0 / 1 / 2 人、NaN・長さ不一致・ゼロベクトルの除外（理由コード込み）。
    2 人ケースでは λ₂ の負クランプ（3.2 手順 6）により y = 0 の 1 次元配置になる
    （NaN が出ない）ことを確認
- `VoiceprintMapLayout.closePairs`: 閾値境界（strictly `<`、`findBestMatch` と同一意味論・Double 昇格比較）、
  ペアの重複なし
- `VoiceprintMapLayout.neighbors`: 距離昇順・`updatedAt` 降順タイブレーク（`KnownSpeakerSort` と同一規則）、
  topN 打ち切り、除外話者が含まれないこと
- `SettingsViewModel`: refresh 後にレイアウト・閾値ペア・近接リストが公開されること、
  閾値の init 注入が効くこと、選択中話者の削除で選択解除されること
